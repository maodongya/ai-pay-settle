## 第1章 文档说明

### 1.1 目的

本文档定义 **ai-pay-settle** 系统的功能规格、非功能规格、模块边界、数据与接口约束，作为产品评审、开发实现、测试验收的统一基线。内容与当前 Maven 多模块代码一致，并标注与生产目标架构的差异。

### 1.2 范围

| 在范围内 | 不在范围内 |
|----------|------------|
| 交易单据接入、清算、计费、清分、结算、对账 | 交易系统订单创建与支付收银台 |
| 中间户余额、提现、T+1 批量打款 | 真实银行渠道对接（当前为 Mock） |
| 计费规则配置与审批（操作台 API） | 完整 RBAC/审批流 UI |
| RocketMQ / 本地 MQ 双模式 | Dubbo 微服务拆分（规划态） |
| MySQL 单库 / 分片 / 7 库垂直拆分目标 | ERP 真实对接 |

### 1.3 读者

- 产品 / 业务：第 1、3、8 章  
- 架构 / 后端：全文  
- 测试：第 3、7、9、10 章  
- 运维：第 11、12 章  

### 1.4 术语

| 术语 | 含义 |
|------|------|
| 清算 | 对单笔交易完成计费、清分、凭证、待结算金额产出 |
| 清分 | 将计费结果拆分为各参与方应收/应付明细 |
| 结算 | 中间户入账、冻结、出款、对账 |
| 中间户 | `merchant_settle_account`，商户待结算账面余额 |
| Outbox | 可靠消息发件箱，保证清分与入账 MQ 最终一致 |
| 分片 | `merchant_id % 16`，与 RocketMQ 16 Queue 对齐 |

## 第2章 系统概述

### 2.1 业务目标

1. 统一接入 8 类交易单据，幂等落库并触发清算  
2. 多维度计费规则匹配，支持固定比例 / 固定金额 / 阶梯递减  
3. 一级代理、二级代理、合伙人、平台、商户多方分润自动计算  
4. 清分明细 + 会计凭证 + Outbox 投递结算金额  
5. 商户中间户托管：入账、退款扣减、挂账冲抵、D0 提现、T+1 批量结算  
6. 全链路监控、积压熔断、死信巡检、补偿 Job  

### 2.2 运行形态

| 维度 | 当前实现 | 生产目标 |
|------|----------|----------|
| 部署 | 单体 `pay-app`（Spring Boot 3.2.5） | K8s 多服务 |
| 数据库 | 默认单库 `pay_settle`；可选 `sharding` Profile | 7 库垂直拆分 + 16 分片 |
| 消息 | `pay.mq.enabled=false` 本地同步；`mq` Profile 走 RocketMQ | RocketMQ 集群 |
| 缓存/锁 | Redis（可关闭，测试用 NoOp 锁） | Redis Cluster |
| 端口 | 18089 | 网关后多实例 |

### 2.3 Maven 模块规格

| 模块 | 规格职责 | 不得包含 |
|------|----------|----------|
| pay-app | 启动、配置聚合、DB 初始化、Actuator | 业务逻辑 |
| pay-api | Service 接口 + DTO | 实现类 |
| pay-common | 枚举、异常、分片工具、限流、Redis 抽象 | 数据库访问 |
| pay-domain | Entity / Mapper / Repository / 分片路由 | 业务流程编排 |
| pay-mq | Topic、Producer、消费基础设施、积压熔断 | 业务 Handler 实现 |
| pay-access | HTTP 接入、trade_pay/refund 消费 | 计费/清分实现 |
| pay-calc | 清算任务编排、重试、监控 | 规则引擎细节 |
| pay-fee | 计费 Pipeline、规则匹配 | 清分/结算 |
| pay-split | 分账、凭证、Outbox 写入与派发 | 账户余额变更 |
| pay-settlement | 入账、提现、T+1、对账、支付回调 | 计费 |
| pay-control | 商户校验、规则管理、告警、工单 | 清算主流程 |
| pay-test | 压测 CLI | 运行时依赖 |

**依赖方向（不得逆向）：** access → calc → (fee + split) → settlement；各业务模块 → domain / api / common / mq。

## 第3章 功能需求规格

### 3.1 单据接入（FR-ACCESS）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR-A01 | 支持 HTTP `POST /api/v1/clearance/bill/submit` 提交单据 | 校验通过则落库 `trade_bill`，返回 billNo |
| FR-A02 | 支持 MQ `trade_pay_topic` / `trade_refund_topic` 接入 | 与 HTTP 路径共用 `BillAccessService` |
| FR-A03 | 幂等：相同 billNo 重复提交不重复落库 | `bill_route` 先查，已存在则直接返回 |
| FR-A04 | 退款单原单未清算时标记 `WAIT_ORIGIN` | 原单 CLEARED 后补偿激活 |
| FR-A05 | 落库与清算触发分离，短事务仅 persist | `persistNewBill` 独立 `@DSTransactional` |
| FR-A06 | 接入层 DB TPS 可限流 | `@DbRateLimit(ACCESS)` 默认 30 TPS |

### 3.2 清算编排（FR-CALC）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR-C01 | 每单创建 `clearance_task`，状态 PENDING→RUNNING→SUCCESS/FAILED/DEAD | 状态机见 08 文档 |
| FR-C02 | 执行顺序：抢占 → 校验 → 计费 → 清分 → 标 SUCCESS | `ClearanceTaskTxSupport` 分阶段短事务 |
| FR-C03 | 计费失败 / 清分失败标 FAILED，退避重试最多 5 次 | `ClearanceRetryJob` 扫描 |
| FR-C04 | 达最大重试标 DEAD 并开工单 | `ExceptionRecordService` |
| FR-C05 | 支持 MQ `clearance_task_topic` 或同步 `executeTask` | `pay.mq.clearance-via-mq` 控制 |
| FR-C06 | calc 层 DB TPS 可限流 | `@DbRateLimit(CALC)` 默认 30 TPS |
| FR-C07 | 提供 calc 积压监控指标 | `ClearanceTaskMetrics` + Prometheus |

### 3.3 计费引擎（FR-FEE）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR-F01 | 规则维度：业务线、品类、服务项、城市、目标类型 |  specificity 打分取最优 |
| FR-F02 | 三种分成模式：固定比例、固定金额、阶梯递减 | 见 04 文档算例 |
| FR-F03 | 退款按原单比例反向冲销 | `calcRefundFee` |
| FR-F04 | 结果持久化 `fee_calc_result`，幂等按 billNo | 重复计费返回已有结果 |
| FR-F05 | 各方金额之和 + 平台费 ≤ 交易本金；负值抛异常 | 不写入结算 |

### 3.4 清分与 Outbox（FR-SPLIT）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR-S01 | 生成 `split_detail` 多方明细 | 平台/代理/合伙人/商户 |
| FR-S02 | 生成 `account_voucher` 复式凭证 | `VoucherGenerator` |
| FR-S03 | 商户收入 ≠ 0 时写 `outbox_message`（status=0） | bizKey=billNo |
| FR-S04 | `OutboxDispatchJob` 分片扫描 pending，sendOrderly 投递 | 不广播全库 |
| FR-S05 | MQ 发送在事务外，markSent 短事务 | `OutboxDispatchTxSupport` |
| FR-S06 | 缺失 Outbox 补偿 | `OutboxCompensateJob` |
| FR-S07 | 缺失 split 补偿 | `SplitCompensateJob` |

### 3.5 结算账户（FR-SETTLE）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR-ST01 | `settle_amount_topic` 消费入账 `creditBalance` | ORDERLY by merchantId |
| FR-ST02 | 入账优先冲抵 `merchant_payable_suspend` 挂账 | 单 SQL `applySettlementOffset` |
| FR-ST03 | 余额入账 CAS 更新 + `account_flow` 流水 | `AccountOperator`，uk(bill_no, op_type) 幂等 |
| FR-ST04 | 退款扣减不足时创建挂账 | status=0 |
| FR-ST05 | D0 提现：校验 → 冻结 → 建单 → 异步出款 | `settlement_order` PAYING |
| FR-ST06 | 支付回调更新订单与提现申请 | 按 settleNo+merchantId，禁止 findAll |
| FR-ST07 | T+1 批量：02:00 扫描 T1 商户全额结算 | `T1BatchJob` |
| FR-ST08 | 失败打款重试 | `PaymentRetryJob` |
| FR-ST09 | 对账单生成 | `ReconcileBillJob` 04:00 |
| FR-ST10 | settlement 层 DB TPS 可限流 | `@DbRateLimit(SETTLEMENT)` 默认 30 TPS |

### 3.6 公共服务（FR-CONTROL）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| FR-CT01 | 商户基础校验（金额&gt;0、商户启用、退款原单存在） | `MerchantValidateServiceImpl`；合约/冻结/分润拆分等见 docs/08「目标态」，**当前未全量实现** |
| FR-CT02 | 计费规则提交（操作台） | `FeeRuleService` 可 submit pending；**审批流未实现** |
| FR-CT03 | 告警：清算 DEAD、MQ 积压、打款失败等 | `AlertService` 落库 + 日志；**外发渠道未接** |
| FR-CT04 | 异常工单开单 | `ExceptionRecordService`；**无关闭/manualRetry API** |

## 第4章 非功能需求规格

### 4.1 性能

| 指标 | 目标值 | 当前压测参考 |
|------|--------|--------------|
| 接入 TPS | 30（限流配置） | 压测 004：~30 TPS 发送 |
| 清算成功率 | ≥ 99.5% | 压测 004：99.8% |
| calc MQ 积压 | Diff < 100 @ 30 TPS | 压测 004：Diff=27 |
| 连接池 active | < maximum-pool-size | Hikari 4~15/28 |
| Outbox 派发批次 | 200 条 / 1s（mq profile） | 可配置 |

### 4.2 可靠性

- **幂等：** 单据、清算任务、账户流水、Outbox 均有业务唯一键  
- **最终一致：** Outbox + MQ；失败可补偿 Job 重放  
- **事务：** 热路径采用短事务，避免 MQ / 外部调用持连  
- **熔断：** `MqBacklogState` 积压超阈值拒绝新单（MQ 模式）  

### 4.3 可观测性

- Actuator：`health`、`prometheus`  
- 业务指标：清算吞吐、Outbox 派发、MQ 生产/消费  
- 日志：关键状态变更 billNo / settleNo / merchantId  

### 4.4 安全

- 操作台 API 需后续接入 JWT/RBAC（规划）  
- 银行卡号存储脱敏展示  
- 结算操作 Redis 分布式锁（merchant 维度）

## 第8章 状态机规格摘要

### 8.1 交易单据 `trade_bill.status`

PENDING → CLEARING → CLEARED / FAILED；退款 WAIT_ORIGIN → PENDING

### 8.2 清算任务 `clearance_task.status`

PENDING → RUNNING → SUCCESS / FAILED / DEAD

### 8.3 结算单 `settlement_order.status`

PAYING → SUCCESS / FAILED

### 8.4 Outbox `outbox_message.status`

0 待发送 → 1 已发送

| Profile | 用途 |
|---------|------|
| mysql | 单库开发/压测 |

### 10.2 关键配置项

```yaml
pay:
  mq.enabled: false              # true=RocketMQ
  mq.clearance-via-mq: true
  mq.outbox-via-mq: true
  outbox.dispatch-interval-ms: 1000
  outbox.dispatch-batch-size: 200
  db-rate-limit:
    enabled: true
    access-tps: 30
    calc-tps: 30
    settlement-tps: 30
  settle.t1-cron: "0 0 2 * * ?"
```
